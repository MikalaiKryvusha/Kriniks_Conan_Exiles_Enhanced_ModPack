# dw.gfx — Графика, погода и производительность

> **Создан:** 2026-09-08 · **Родитель:** docs/03-cvars-конана.md · **Статус:** черновик,
> ни одна строка не проверена в живой игре · **Вовне:** —

`gfx` — не настоящий префикс. Настоящий префикс один на всю игру: `dw.`. «gfx» — наш ярлык
семьи, которым `_config/split-dw-families.py` разложил 264 имени по девяти корзинам. В этой
корзине **16 имён**.

---

## Коротко: зачем сюда идти

Сюда идут с тремя симптомами. **«На дальних планах висит муть»** — хотя объёмный туман уже
выключен штатным выключателем игры (`Game.ini` → `[Settings.Video] VolumetricFog=0`), и надо
понять, добавит ли что-то к этому пара `dw.LowPerformance*`. **«Трава растёт сквозь пол базы»**
— за это отвечает собственная система Конана `dw.GrassOcclusion*`, которой в ванильном Unreal
нет. **«Кадры проседают, когда начинается буря»** — тогда смотрят на `dw.DisableWeatherSystem`
и на отладочную печать погоды.

Предупреждение на входе: **две главные ручки этой семьи опасны именно тем, что выглядят
понятными.** По имени `dw.LowPerformanceFog` невозможно сказать, что делает единица —
включает дешёвый режим или выключает его. Раздел «Что стоит попробовать» даёт заход консолью,
который отвечает на это за пять минут; гадать не надо.

## Как это устроено

### Что мы нашли в сети и чего не нашли

Половина ценности этого файла — честный отчёт о поиске, поэтому он идёт первым.

Из 16 имён семьи **два** встречаются в открытых источниках: `dw.DisableWeatherSystem` и
`dw.GUIForceGarbageThreshold` — оба в дампе клиентских консольных команд на официальной вики
([List of admin commands](https://conanexiles.fandom.com/wiki/List_of_admin_commands), проверено
08.09.2026 выборкой по всем 16 именам). Остальные **четырнадцать не встречаются нигде**:

- поиск GitHub по коду (`gh api search/code`) по точным именам — **0 совпадений** на каждое;
- полнотекстовый поиск форума Funcom (`forums.funcom.com/search.json`) по `LowPerformanceFog`,
  `LowPerformanceMaterials`, `DisableWeatherSystem`, `WaterInteraction`, `SkyHelper`,
  `LowPerformance` — **пусто по всем**;
- обычный веб-поиск по именам в кавычках — ни одного документа, только пересказы общих гайдов.

Это нормальный результат: `dw.*` — закрытый слой Funcom, и вики-дамп сделан ещё в эпоху UE4.
Пустой поиск, названный честно, дороже придуманного объяснения.

### Единственная прямая находка: система GameTweak, и почему она важна

Поиск дал одну настоящую зацепку, и она про траву. В логе игры, выложенном на форуме Funcom,
есть строка:

```
LogGameTweakSystem:Display: GameTweak 'GrassOcclusion' set to 'true'
```

([forums.funcom.com, тред «Fatal error Line959»](https://forums.funcom.com/t/fatal-error-line959/237425)
— там же выложен полный список: `NavGenerationAroundPlayer`, `DynamicLevelActivation`,
`BuildingPersistenceOptimization`, `PoiProtection` и десятки других.)

Отсюда три вывода.

**Первый: окклюзия травы — это фича-флаг, а не только набор cvar-ов.** Над семью
`dw.GrassOcclusion*` стоит выключатель `GameTweak 'GrassOcclusion'`, и если он выключен, ручки
ниже бессмысленны.

**Второй: флаги приезжают по сети.** Funcom Live Services отдаёт «build overrides» на старте.
На машине владельца это **не работает** — наблюдение, лог сессии 07.09.2026:

```
LogHttp: Warning: POST https://services.live.exiles.wintercloud.net/api/GetBuildOverrides
         completed with reason 'ConnectionError' after 0.16s
LogFuncomLiveServices: Error: GetBuildOverrides Failed
LogGameTweakSystem: Warning: Failed to receive build overrides from FLS
```

(файл `D:\Games\Conan Exiles\ConanSandbox\Saved\Logs\ConanSandbox.log`, три раза за сессию).
Значит у владельца действуют **вшитые в сборку значения GameTweak-ов**, и списка их в логе нет —
строк вида `GameTweak '…' set to '…'` в его логе ноль. Какой в этой сборке вшит `GrassOcclusion`,
мы **не знаем**.

**Третий: лог — главный прибор этой семьи.** Он же показывает, какие cvar-ы игра ставит себе
сама. Формат ровно такой (наблюдение, тот же лог):

```
LogConfig: Applying CVar settings from Section [/Script/ConanSandbox.SystemSettings] File [Engine]
LogConfig: Set CVar [[dw.EnableStaticRoamingPaths:0]]
LogConfig: Set CVar [[grass.CullDistanceScale:1.6]]
```

Всего в сессии 07.09.2026 игра выставила себе **58 имён `dw.*`** — и **ни одного из наших 16**.
Проверено поимённо: `GrassOcclusion`, `LowPerformance`, `Weather`, `WaterInteraction`,
`SkyHelper`, `StartingEmote`, `GUIForceGarbage`, `PhysicsBodyCreation` — все нули. Вывод, который
стоит запомнить: **все 16 стоят на умолчаниях сборки**, их никто не трогает ни из ini игры, ни из
её конфигов. Значит наш `Engine.ini` по этим именам ни с кем не спорит — в отличие от семьи
тик-рейтов, где блок игры `[/Script/ConanSandbox.SystemSettings]` применяется **позже** нашего
`[SystemSettings]` и с тем же приоритетом.

Второй формат строк, который надо уметь узнавать, — отказ по приоритету:

```
LogConsoleManager: Warning: Setting the console variable 'r.Nanite.MaxVisibleClusters'
  with 'SetBySystemSettingsIni' was ignored as it is lower priority than the previous
  'SetByDeviceProfile'. Value remains '2097152'
```

Четыре такие строки в логе владельца — и это живое подтверждение лестницы приоритетов из
`01-графика-и-DLSS.md`, раздел 5: **профиль устройства бьёт наш ini**. Ни одно имя из этой семьи
в отказах не значится.

### Окклюзия травы: один механизм из семи ручек

Ванильный Unreal траву под постройками не убирает. В UE5 у ландшафта есть заготовка под это —
`ALandscapeProxy::AddExclusionBox` / `RemoveExclusionBox` / `RemoveAllExclusionBoxes`, и даже
консольные ручки к ней (`grass.DumpExclusionBoxes`, `grass.IgnoreExcludeBoxes` — оба есть в нашем
дампе реестра). Но разбор исходников показывает, что **сам движок этим API практически не
пользуется**: боксы должна поставлять игра
([UE5 Landscape Grass Source Analysis](https://wh0.is/posts/a-look-under-the-hood-at-unreal-engine-landscape-grass-en)).
`dw.GrassOcclusion*` — и есть эта игровая половина работы. Заодно это объясняет, почему тема
годами висела в фидбеке: [«Grass and vegetation through foundations»](https://forums.funcom.com/t/grass-and-vegetation-through-foundations/90792).

Как это читается по именам — единой картиной, а не списком:

**Мир режется на тайлы (`TileSize`), тайл — на ячейки (`CellSize`).** Тайл — единица работы:
его строят и выбрасывают по мере движения игрока, как чанк. Ячейка — единица разрешения: именно
ячейкой система отвечает «здесь постройка — травы нет». Отсюда прямая цена точности: **уменьшили
ячейку вдвое — площадь ячейки упала вчетверо, значит ячеек на тот же тайл вчетверо больше**, и
во столько же раз растут и проверки, и память под маску. Уменьшили тайл — граница травы поедет
за игроком чаще, то есть перестройки станут мельче, но их станет больше.

**Постройку ищут трассой вниз (`BuildableTraceHeight`).** Чтобы понять, накрыта ли ячейка полом,
надо пустить луч и посмотреть, во что он упрётся. Высота трассы — это компромисс: мало —
пропустим пол, поднятый на фундаментах или сваях (трава полезет сквозь настил второго этажа);
много — каждая ячейка платит за более длинный луч, а под многоэтажной базой луч начнёт цеплять
перекрытия, которых он цеплять не должен.

**Прячут не ячейки, а инстансы травы.** Трава в UE — это инстансированные меши, у каждого
инстанса свой bounds. `InstanceBoundsScale` раздувает или сжимает эти границы перед проверкой
пересечения: больше единицы — трава исчезает **с запасом**, то есть чисто внутри дома, но с
проплешиной по кругу снаружи; меньше единицы — трава жмётся вплотную к стене и лезет сквозь
край пола.

**`MaxOccludedInstanceHeight` — предохранитель.** Он отделяет «траву», которую прятать можно, от
кустов и молодых деревьев, которые прятать нельзя, иначе вокруг базы начнёт мигать крупная
растительность. Порог по высоте инстанса.

**Две оставшиеся ручки — глаза.** `ShowDebug` рисует саму сетку и решения, а
`ShowRecentlyOccludedInstancesBounds` — границы того, что только что спрятали. Без них настройка
первых пяти — это тыканье вслепую, поэтому в порядке проверок они идут **первыми**.

### Туман: что уже сделано и что эта семья может добавить

В сборке уже стоит `VolumetricFog=0` — штатный выключатель игры. Он гасит **объёмную** часть
тумана: ту, что считается в 3D-сетке и даёт лучи света. Он **не трогает** ни высотный туман, ни
атмосферную перспективу — а это и есть основная «муть» на горизонте. Четыре независимые системы
дымки и их рычаги разобраны в `01-графика-и-DLSS.md`, раздел 6; здесь важен один вопрос: что
добавит `dw.LowPerformanceFog`.

Честный ответ: **неизвестно, и направление тоже неизвестно.** Имя не содержит ни `Enable`, ни
`Disable` — в отличие от соседей по этой же семье (`dw.DisableWeatherSystem`,
`dw.EnableWeatherDebugPrint`). Поэтому единица может означать и «включить дешёвый туман для
слабых машин», и «пометить, что туман тяжёлый, и выключить его». Первое прочтение вероятнее —
но вероятнее это не знание.

Зато есть **дешёвый способ узнать, дубль это или добавка**, и он занимает один заход: прочитать
`r.VolumetricFog` (ввести имя без значения), затем переключить `dw.LowPerformanceFog` и прочитать
`r.VolumetricFog` снова. **Если движковое значение поехало следом — dw-ручка внутри просто дёргает
`r.VolumetricFog`, то есть это дубль уже сделанного.** Если движковое значение не шелохнулось, а
картинка изменилась — она трогает что-то своё, и это добавка. Процедура целиком — ниже.

`dw.LowPerformanceMaterials` к дымке отношения не имеет вовсе: материалы — это шейдеры
поверхностей. Если направление окажется «1 = дёшево», то это ручка **ухудшения** картинки, и
владельцу, который просил «повысить графику», нужна противоположная.

### Погода: почему её не стоит выключать

Погода в Конане — не украшение. Песчаная буря это статус-эффект: *«It is very important that you
prepare for the sandstorm, as it will kill you»*, а укрытие ищут по индикатору Shelter — пещеры и
расщелины дают его полностью
([Sandstorm, офиц. вики](https://conanexiles.fandom.com/wiki/Sandstorm)). В версии Enhanced
погодные эффекты вдобавок переписаны: по разбору патчноутов, «Converted Sandstorm VFX to Niagara»
и «Converted all precipitation VFX to Niagara», а «Sandstorms no longer appear inside dungeons» и
«Diving prevents sandstorm damage»
([разбор патчноутов Enhanced, BisectHosting](https://www.bisecthosting.com/blog/conan-exiles-enhanced-update-release-date-patch-notes-changes-new-features)
— пересказ, не первоисточник Funcom).

Отсюда практический вывод: **если кадры валятся именно в бурю, виноват Niagara-эффект бури, а не
«погода» вообще**, и правильный первый шаг — не выключатель системы, а отладочная печать
`dw.EnableWeatherDebugPrint`, чтобы точно знать, что на экране буря, а не совпадение.

### Мелочь семьи

Оставшиеся четыре имени к «графике» относятся косвенно, но лежат здесь по смыслу.
`dw.GUIForceGarbageThreshold` — порог принудительной сборки мусора со стороны интерфейса; в UE
сборка мусора это **пауза игрового потока**, то есть микрофриз, и у движка на этот счёт свои
ручки, видные в логе владельца: `gc.TimeBetweenPurgingPendingKillObjects:61.1`,
`gc.MaxObjectsNotConsideredByGC:42000`, `gc.NumRetriesBeforeForcingGC:10`.
`dw.WaterInteraction.Enabled` — взаимодействие с водой; в игре подключён движковый плагин Water
(наблюдение: в `Engine.ini` есть `Paths=../../../Engine/Plugins/Experimental/Water/Content`, а в
реестре — 25 имён `r.Water.*`, включая `r.Water.EnableShallowWaterSimulation`).
`dw.SkyHelperVolumeBoundsCheckingEnabled` — проверка вхождения игрока в объём, который «помогает
небу»: в UE так устроены `APostProcessVolume` и `AAudioVolume`, они спрашивают
`EncompassesPoint` для точки камеры. `dw.StartingEmoteInSectionEnabled` — про секции монтажа
анимации.

## Что стоит попробовать владельцу

Порядок именно такой: сначала то, что ничего не меняет и превращает гипотезы в факты, потом то,
что меняет картинку.

### 1. Заход-разведка: существуют ли эти имена вообще (5 минут, ничего не меняет)

Имя, найденное в бинарнике, — **ещё не cvar**. Движок молча глотает неизвестное имя: ни ошибки,
ни следа. Единственное доказательство — чтение значения в живой игре.

ESC → Настройки → Настройки сервера → **«Сделать меня администратором»**. Консоль: **Insert**,
**Tilde** или **F10**. Вводить имена **без значения**, по одному, и записывать, что ответила
консоль:

```
dw.LowPerformanceFog
dw.LowPerformanceMaterials
dw.GrassOcclusionCellSize
dw.GrassOcclusionTileSize
dw.GrassOcclusionBuildableTraceHeight
dw.GrassOcclusionInstanceBoundsScale
dw.GrassOcclusionMaxOccludedInstanceHeight
dw.GrassOcclusionShowDebug
dw.GrassOcclusionShowRecentlyOccludedInstancesBounds
dw.DisableWeatherSystem
dw.EnableWeatherDebugPrint
dw.EnablePhysicsBodyCreationDebugSpheres
dw.GUIForceGarbageThreshold
dw.SkyHelperVolumeBoundsCheckingEnabled
dw.StartingEmoteInSectionEnabled
dw.WaterInteraction.Enabled
```

Отдельно стоит **набрать `dw.LowPerf` и не нажимать Enter**: консоль UE показывает подсказку со
списком совпадений, и если Funcom написал к переменной help-строку, она будет видна прямо там.
Одна такая строка снимает весь вопрос о направлении.

Эффект: 16 гипотез превращаются в факты «есть/нет» и в 16 действующих значений. Цена: ноль.
**Это самый выгодный заход во всём файле.**

### 2. Направление `LowPerformance*` — за один заход, без гадания

Идея простая: пусть направление покажет **сама игра**.

1. Прочитать `dw.LowPerformanceFog` и `dw.LowPerformanceMaterials` (пункт 1).
2. Прочитать `r.VolumetricFog` — записать.
3. ESC → Настройки → Графика → переключить пресет качества на **самый низкий** → применить →
   вернуться в мир → **прочитать оба dw-имени снова**.
4. Если значение изменилось — **то, которое встало на низком пресете, и есть дешёвый режим.**
   Это ответ, а не догадка. Если не изменилось — игра эти ручки своим меню не трогает, и
   направление придётся определять глазами (пункт 5).
5. Вернуть свой пресет. Прочитать значения ещё раз.
6. Проба на дубль: переключить `dw.LowPerformanceFog` на противоположное и снова прочитать
   `r.VolumetricFog`. **Поехало — дубль уже сделанного `VolumetricFog=0`.** Не поехало —
   ручка своя.
7. Проба глазами: одна и та же точка с видом на горизонт, скриншот при `0` и при `1`. Сравнивать
   не «красивее», а конкретно: видно ли дальние скалы, есть ли ступенька на границе тумана.
8. После выхода из игры — грепнуть лог:
   `Select-String -Path "D:\Games\Conan Exiles\ConanSandbox\Saved\Logs\ConanSandbox.log" -Pattern "LowPerformance|LogConsoleManager"`

### 3. Трава под базой — там, где эта семья действительно окупается

Порядок: `ShowDebug 1` → если ничего не нарисовалось, **всю ветку закрыть** (система выключена
GameTweak-ом, и cvar-ы бессильны). Если нарисовалось — дальше по одному изменению за заход:
`InstanceBoundsScale` (самая дешёвая и самая заметная), затем `CellSize`, затем
`BuildableTraceHeight`. `TileSize` — последним.

Замер обязателен на одной и той же точке до и после, прибором `_tools/perf-harness/`, по медианам
и перцентилям, а не по средним.

### 4. Погода — не выключать

Вместо `dw.DisableWeatherSystem` включить `dw.EnableWeatherDebugPrint 1` на одну сессию и
посмотреть, совпадают ли просадки с бурей. Если совпадают, дешёвая часть решения лежит **не в
этой семье**, а в Niagara: буря в Enhanced — Niagara-система, и у неё свои ручки масштабирования
(`fx.Niagara*`, семья `fx` — соседний файл конспекта).

### 5. Дымка, если после `VolumetricFog=0` муть осталась

Идти **не в `dw.`, а в `r.`** — просто потому, что про движковые имена у нас есть справка, а про
`dw.` нет ничего. У `r.Fog` help-строка прямая: `0: disabled / 1: enabled (default)`, и ноль
гасит **все** туманы разом
([UE cvar wiki, r.Fog](https://indxzero.github.io/ue544cvarwiki/articles/r.fog/)). Это грубый
рычаг: вместе с дымкой уходит ощущение глубины сцены. Порядок и остальные три системы дымки —
`01-графика-и-DLSS.md`, раздел 6.

### 6. Чего делать не надо

Не включать `dw.EnablePhysicsBodyCreationDebugSpheres` и
`dw.GrassOcclusionShowRecentlyOccludedInstancesBounds` дольше, чем нужно на один взгляд: это
отладочная отрисовка, она стоит кадров и ничего не улучшает. Не трогать
`dw.StartingEmoteInSectionEnabled` — к запросу владельца отношения не имеет.

## Чего мы не знаем

Список честный, и он длиннее, чем хотелось бы.

1. **Существуют ли эти 16 cvar-ов в реестре консоли.** Имена взяты сканом строк бинарника, а не
   из реестра. Ни одно не подтверждено чтением в живой игре.
2. **Ни одного значения по умолчанию.** Не знаю, читается консолью. В логе запуска у владельца
   нет ни одной из 16 строк `Set CVar`, значит игра их не выставляет — но какие константы вшиты
   в сборку, оттуда не видно.
3. **Направление `dw.LowPerformanceFog` и `dw.LowPerformanceMaterials`** — включатель дешёвого
   режима или выключатель. Это главный пробел файла, и он закрывается заходом из пункта 2.
4. **Типы переменных.** Булев ли `LowPerformanceFog` или это шкала 0…3 — неизвестно.
5. **Единицы измерения** у `CellSize`, `TileSize`, `BuildableTraceHeight`,
   `MaxOccludedInstanceHeight`. Сантиметры Unreal — правдоподобно, но не проверено; у
   `GUIForceGarbageThreshold` единица не угадывается вовсе (мегабайты? число объектов? число
   виджетов?).
6. **Клиентские они или серверные.** В одиночной игре это listen-сервер в клиенте, так что
   практической разницы может и не быть, — но для семьи `GrassOcclusion` вопрос не праздный:
   решение «где стоит постройка» естественно принимать на сервере, а прятать траву — на клиенте.
7. **Какое значение вшито в GameTweak `GrassOcclusion` у владельца.** Форумный лог 2023 года
   показывает `true`, но это другая эпоха и другой билд; у владельца FLS не отвечает
   (`Failed to receive build overrides from FLS`), поэтому список активных GameTweak-ов в его
   логе вообще не печатается.
8. **Ни одного замера кадров.** Все «чем платим» описаны механизмом, а не числом. Числа появятся
   только после `_tools/perf-harness/`.
9. **Что такое «Section» в `StartingEmoteInSectionEnabled`.** Секция монтажа анимации — самое
   правдоподобное прочтение, но «section» в кодовой базе Funcom может означать и секцию ini, и
   участок карты.
10. **Есть ли на Изгнанных землях хоть один SkyHelperVolume.** Если объёмов нет, ручка проверки
    границ ничего не переключает, и наблюдение в пещере даст ложный отрицательный ответ.
11. **Четырнадцать имён из шестнадцати не описаны нигде в открытых источниках** — ни в коде на
    GitHub, ни на форуме Funcom, ни в вебе. Это результат поиска, а не его отсутствие: искали
    точными именами в кавычках, поиском по коду и полнотекстовым поиском форума.
